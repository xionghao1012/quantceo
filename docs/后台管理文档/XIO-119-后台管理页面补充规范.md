# 后台管理页面补充规范

> XIO-118 子规范：为运营统计页面和 OAuth 应用管理页面建立完整规范。

---

## Problem Statement

后台管理系统已完成基础功能（用户管理、订单审核），但存在两处有 API 但缺前端页面的情况，导致管理后台不完整：

1. **运营统计页面**：后端 `/api/admin/stats` 已实现，前端未调用，管理员无法在界面上看到平台运营概况。
2. **OAuth 应用管理页面**：quant-sso 后端已完整实现 OAuth 应用的 CRUD + rotate-secret，前端页面完全缺失，ops 角色无法管理第三方应用。

---

## Solution

在现有 `AdminView.vue` 中新增两个 Tab 页面，延续现有 UX 模式（Admin Key 认证、权限驱动菜单、表格操作）。

---

## User Stories

1. 作为 ops 角色管理员，我想要在 `/admin/oauth-apps` 查看所有 OAuth 应用列表（名称、client_id、redirect URIs、scopes、启用状态），以便管理第三方接入。
2. 作为 ops 角色管理员，我想要在 `/admin/oauth-apps` 创建新 OAuth 应用（填写名称、redirect URIs、scopes、IP 白名单），系统自动生成 client_id 和 client_secret，以便第三方开发者注册应用。
3. 作为 ops 角色管理员，我想要在 `/admin/oauth-apps` 编辑已有应用（修改名称、redirect URIs、scopes、IP 白名单、active 状态），以便管理应用配置。
4. 作为 ops 角色管理员，我想要在 `/admin/oauth-apps` 禁用/启用应用（切换 active 状态），以便快速吊销失控应用而不删除记录。
5. 作为 ops 角色管理员，我想要在 `/admin/oauth-apps` 重置应用密钥（rotate-secret），新 secret 只在创建时显示一次，后续重置才重新显示，以便应用密钥泄露后及时轮换。
6. 作为 ops 角色管理员，我想要在 `/admin/oauth-apps` 删除应用，以便移除废弃应用。
7. 作为任意登录管理员，我想要在 `/admin` 概览页看到运营统计卡片（总用户数、Pro 用户数、待审核订单数），以便快速了解平台状态。
8. 作为前端开发，我想要新增页面复用现有 `adminHeaders()` 认证模式和 `hasPerm()` 权限过滤，以便保持与现有代码风格一致。

---

## Implementation Decisions

### 模块修改

**quant-trading/src/client/views/AdminView.vue**

- 新增 `statsTab` ref，调用 `GET /api/admin/stats`，展示三个统计卡片
- 新增 `oauthAppsTab` ref，调用 `GET ${SSO_URL}/api/auth/applications`（通过 Vite proxy 或直接 URL）
- 新增 `StatsSection` 组件内嵌或直接写在 AdminView template 中
- 新增 `OAuthAppsSection` 组件内嵌或直接写在 AdminView template 中
- 新增 `showAppModal` ref + `editingApp` ref，支持创建/编辑弹窗
- 新增 `confirmDelete` ref + `deletingAppId` ref，支持删除确认弹窗

**quant-trading/src/client/stores/auth.ts**（如需要）

- 如 quant-sso 认证需要单独 token，确认是否复用 `adminKey` 或新增 `ssoAdminKey`

**quant-trading/vite.config.ts**

- 如 quant-sso 与 quant-trading 不同源，需配置 proxy 将 `/api/sso/admin/*` 转发到 `${SSO_URL}/api/auth/applications/*`

**quant-trading/src/server/routes/admin.ts**

- 确认 `/api/admin/stats` 路由是否存在且可访问（已确认存在）

### 接口契约

#### GET /api/admin/stats

响应：
```json
{ "totalUsers": 1523, "proActive": 87, "pendingOrders": 12 }
```

#### GET /api/auth/applications（quant-sso）

响应：
```json
{
  "applications": [{
    "id": 1,
    "name": "TradingView Alert Bridge",
    "clientId": "cid_abc123...",
    "redirectUris": ["https://tradingview.com/webhook"],
    "scopes": ["orders:write", "positions:read"],
    "ipWhitelist": [],
    "active": true,
    "createdAt": "2026-07-01T00:00:00Z",
    "updatedAt": "2026-07-10T00:00:00Z"
  }]
}
```

#### POST /api/auth/applications（quant-sso）

请求：
```json
{ "name": "...", "redirectUris": [], "scopes": [], "ipWhitelist": [] }
```
响应（201）：
```json
{
  "id": 2,
  "name": "...",
  "clientId": "cid_xxx",
  "clientSecret": "cs_xxx",  // 仅创建时返回
  "redirectUris": [],
  "scopes": [],
  "createdAt": "..."
}
```

#### PUT /api/auth/applications/:id（quant-sso）

请求：
```json
{ "name": "...", "redirectUris": [], "scopes": [], "ipWhitelist": [], "active": true }
```

#### POST /api/auth/applications/:id/rotate-secret（quant-sso）

响应：
```json
{ "clientSecret": "cs_new_xxx" }
```

#### DELETE /api/auth/applications/:id（quant-sso）

响应：`{ "success": true }`

### 路由与菜单

- `/admin` 已有 Tab 导航：Pending Orders、User Management
- 新增 Tab：Stats（所有管理员可见）或整合到现有概览区
- 新增 Tab：OAuth Apps（需要 `oauth.manage` 权限，`requireAdminRole('oauth.manage')` 在后端已配置）
- OAuth Apps 路由对应 `requireAdminRole('oauth.manage')`，前端用 `hasPerm('oauth.manage')` 控制显示

### SSO URL 配置

- quant-sso 服务 URL 通过 `import.meta.env.VITE_SSO_URL` 传入
- 开发环境：`VITE_SSO_URL=http://localhost:3002`
- 生产环境：配置对应 SSO 服务地址

### 权限设计

- Stats 页面：任何登录管理员可见（`isAdmin || hasPerm('stats.view')`）
- OAuth Apps 页面：仅 `oauth.manage` 权限可见（后端 enforce `requireAdminRole('oauth.manage')`）

### 数据模型（quant-sso applications 表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | serial | 主键 |
| name | varchar(100) | 应用名称 |
| clientId | varchar(64) | 唯一客户端 ID（cid_ 前缀） |
| clientSecret | varchar(128) | 客户端密钥（cs_ 前缀） |
| redirectUris | jsonb | 重定向 URI 列表 |
| scopes | jsonb | 授权范围列表 |
| ipWhitelist | jsonb | IP 白名单列表 |
| active | boolean | 是否启用 |
| createdAt | timestamp | 创建时间 |
| updatedAt | timestamp | 更新时间 |

## Testing Decisions

### Stats 页面测试

1. 登录为 admin 用户，访问 `/admin`，验证三个统计数字正常显示
2. 使用 admin key 认证，验证统计数字正常显示
3. 验证数字格式正确（千分位分隔符）

### OAuth Apps 页面测试

1. ops 角色登录，访问 `/admin/oauth-apps`，验证应用列表正常加载
2. 非 ops 角色登录，验证页面不在菜单中显示
3. 创建应用：填写表单，验证 client_id + client_secret 在提交后正确显示
4. 编辑应用：修改名称/redirect URIs，验证更新成功
5. 禁用/启用：切换 active 状态，验证列表中状态同步更新
6. 重置密钥：点击 rotate-secret，验证新密钥显示且旧密钥失效
7. 删除应用：确认删除，验证应用从列表移除

### 测试原则

- 仅测试外部可观察行为（UI 状态、API 响应），不测试内部实现
- 使用 Playwright 做 E2E 测试

---

## Out of Scope

- 角色管理 UI（XIO-82 定义为 SQL 管理，不做前端 UI）
- 权限管理 UI（初期通过迁移脚本管理）
- OAuth 应用申请注册流程（只做管理界面，不做开发者自助申请）
- Stats 历史趋势图（只做当前数字展示，不做时间序列图）
- 批量操作 OAuth 应用

---

## Further Notes

- OAuth Apps 页面依赖 quant-sso 服务可用性，需确保 SSO 服务正常在线
- clientSecret 仅在 `POST /`（创建）和 `POST /:id/rotate-secret` 时返回，之后不再返回明文，前端需在创建/重置后即时展示并提示管理员保存
- XIO-82 文档中 OAuth Apps 属于 ops + admin 角色，本规范遵循该权限矩阵
